\# FishMap Project Milestones and Schedule



\## 1. Purpose



This document defines the main milestones for the FishMap diploma project. Each milestone has a clear deliverable and is aligned with the project's pre-defense and final defense stages.



Exact dates for individual milestones will be confirmed when the academic schedule is finalized.



\## 2. Project Milestones



| Milestone | Description | Deliverable |

|---|---|---|

| Requirements and Planning | Define project objectives, functional requirements, scope, and research background. | Project proposal and requirements document |

| Architecture and Design | Define the system architecture, backend services, database structure, and API contracts. | Architecture diagram, database design, and API specification |

| Initial Implementation | Implement the backend foundation, authentication, user profiles, and database integration. | Working backend foundation |

| Core Feature Development | Implement fishing spots, catches, inventory management, and social features. | Functional FishMap prototype |

| `pre-defense-1` | Present the project concept, requirements, architecture, and initial progress. | Progress report and presentation |

| Continued Development and Testing | Complete core features, verify API behavior, and resolve identified defects. | Updated prototype and test results |

| `pre-defense-2` | Present implementation progress and demonstrate the main application features. | Working prototype and progress presentation |

| Final Testing and Documentation | Complete verification, document the implementation, and prepare the final presentation. | Test report, diploma documentation, and presentation |

| `final-pre-defense` | Review the completed project and prepare for the official diploma defense. | Final project version and defense-ready presentation |

| Final Diploma Defense | Demonstrate and defend the completed FishMap diploma project. | Final diploma project and presentation |

\## 4. Completion Criteria



A milestone is considered complete when its deliverable has been prepared, reviewed, and recorded in the project repository or other agreed project documentation.



Each milestone should have:

\- A defined objective.

\- A specific deliverable.

\- Verifiable completion criteria.

\- A status indicating whether it is planned, in progress, or completed.



\## 5. Schedule Updates



The schedule will be updated when the university confirms the individual pre-defense dates or when project requirements change. Changes should be documented so that the team can track progress and upcoming deliverables.

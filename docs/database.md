# Database ownership

FishMap keeps data ownership with the service that owns its business capability. Services never access another service's repositories or tables directly. A single PostgreSQL server may host multiple logical service databases during early development, but this does not change the ownership boundary.

## Auth Service

The Auth Service owns the `fishmap_auth` database. Its first schema contains the `auth_users` table, managed only through Auth Service migrations and repositories.

| Column | Type | Notes |
| --- | --- | --- |
| `id` | UUID | Primary key; generated by the Auth Service model. |
| `email` | VARCHAR(320) | Required; unique, case-insensitive through a unique `LOWER(email)` index. |
| `username` | VARCHAR(30) | Required; unique, case-insensitive through a unique `LOWER(username)` index. |
| `password_hash` | VARCHAR(255) | Required credential-hash storage; plaintext passwords are never persisted. |
| `account_status` | VARCHAR(20) | Required account state; initially `active`. |
| `created_at` | TIMESTAMPTZ | Creation timestamp. |
| `updated_at` | TIMESTAMPTZ | Last-update timestamp. |

The initial migration also adds an index on `account_status`. Password hashing, account creation, and authentication behavior are implemented in later phases.

## Local development

The root `docker-compose.yml` starts PostgreSQL for local Auth Service development. Configuration is supplied from the ignored `backend/services/auth/.env`; use that service's `.env.example` as the checked-in template. The container's PostgreSQL port is `5432`; the default host port is `5434` to avoid colliding with existing local PostgreSQL installations. The Auth Service connects through `AUTH_DATABASE_URL` and never embeds credentials in source code.
